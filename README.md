# 압박 트리거 해부도 — UEFA Euro 2024

StatsBomb 오픈데이터(이벤트 + 360)로 유로 2024의 압박을 **트리거 단위**로 분해한 분석이다.
대회 51경기 전수·24개국을 같은 파이프라인으로 돌렸고(압박 온셋 9,267회),
스페인 7경기(687회)를 심층 분석했다.

📊 **[리포트 보기](https://claude.ai/code/artifact/77f07e91-9012-43f3-9f61-e6284a3bd5b7)**

## 무엇을 물었나

압박을 다루는 분석은 대개 PPDA 한 숫자와 압박 위치 밀도 히트맵에서 멈춘다.
두 지표는 "얼마나 자주" "어디서" 눌렀는지는 말해주지만, 현장에서 필요한 질문에는 답하지 못한다 —
**무엇에 반응해서 눌렀는가**, 그리고 **그 반응은 공을 되찾아 줬는가**.

전력분석 미팅에서 코치가 쓰는 언어는 지표가 아니라 상황이다.
"백패스 나오면 간다", "터치라인으로 몰면 간다", "골킥은 놓아주고 세컨볼만 잡는다".
이 저장소는 그 언어를 데이터 구조로 옮기고, 각 트리거가 실제로 몇 퍼센트를 회수했는지 값을 매긴다.

### Press Chain — 압박을 4단계 연쇄로 정의한다

```
① 트리거          ② 수렴              ③ 회수           ④ 전진
상대가 취약해지는  →  압박 팀이 볼 주변으로  →  소유권을      →  회수 위치가
순간이 발생        좁혀 들어간다          되찾는다        기회로 이어진다
```

각 단계에서 얼마가 새는지를 측정하면 "압박이 강했다"가 아니라
"어느 연결고리가 끊겼다"로 말할 수 있다.

## 주요 결과

| 발견 | 근거 |
|---|---|
| **압박 성과를 가르는 것은 강도가 아니라 라인 높이** | 수비 액션 높이 ↔ 회수율 `r=+0.774 (R²=0.599)`. PPDA는 `r=−0.662`, 90분당 압박 횟수는 `r=−0.534`로 **음(−)** |
| **스페인의 압박은 전면적이 아니라 선택적** | GK 소유 시 수렴 0.82명(타 트리거의 1/3), 스로인·공중볼에서는 1초 만에 3.8명 투입 |
| **최다 사용 트리거가 최저 효율** | 터치라인 압착 30.0%(최다) → 회수율 23.8%, 파이널서드 회수 1.9% |
| **최고 효율은 공중볼 경합** | 4.1%에 불과하나 회수율 46.4%, 파이널서드 회수 21.4%, 회수 중앙시간 1.85초 |
| **물량·수렴은 성과의 대리 지표가 아님** | 슬로베니아 압박 횟수 1위 → 회수율 24위. 조지아 수렴 1위 → 회수율 23위 |
| **수렴 지수는 팀을 구분하지 못함** | 24개국이 2.05~2.69에 몰려 변동계수 5.1% (회수율은 18.3%) |

스페인 구역별 회수율은 좌측 채널에서 하프라인을 넘는 순간부터
**31.1% → 36.7% → 47.8%** 로 단조 증가하고, 중앙 전진 구역은 **14.0%(n=50)** 로 전체 최저다.

## 방법론 — 조용히 틀리는 지점 셋

공개 데이터를 그대로 집계하면 코드는 정상 실행되고 차트도 그럴듯하게 나오지만
결론이 뒤집히는 오류가 세 군데 있다.

### 1. 압박 온셋과 트리거를 분리한다

`Pressure` 이벤트는 한 번의 압박 국면에서 여러 건이 연달아 찍힌다. 그대로 세면 압박 횟수가 부풀려진다.
직전 5초 내 동일 팀 Pressure가 없는 첫 건만 **온셋**으로 채택해 국면 단위로 압축하고
(스페인 7경기: Pressure 1,126건 → 온셋 687건), 온셋 직전 6초 내 상대의 마지막 온볼 이벤트를
**트리거**로 역추적한다. 분석 단위가 "우리 수비 행위"에서 "상대의 취약 순간"으로 이동한다.

### 2. `play_pattern`의 지속성을 보정한다

`play_pattern`은 재개 상황 이후 **포제션 전체에 계속 붙어 있다**.
스로인 20초 뒤의 패스도 여전히 `From Throw In`이다.
보정 전 스로인·골킥이 전체 트리거의 39%를 차지했다.
재개 라벨을 포제션 선두 2~3개 이벤트로 게이팅하면 스로인 139→33건, GK 132→69건으로 정상화되고
미분류 비중도 47.6%→22.0%로 떨어진다.

### 3. 360의 가시성 편향을 보정한다

360 프리즈프레임은 **방송 카메라에 잡힌 선수만** 기록한다(프레임당 평균 16.5명 / 22명).
볼 주변 압박자를 그냥 세면 카메라가 넓게 잡은 장면일수록 압박이 약해 보이는
**방향이 정해진 오차**가 생기고, 이런 편향은 표본을 늘려도 사라지지 않는다.
각 프레임의 `visible_area` 폴리곤 대비 반경 10.4m 원판의 커버리지를 몬테카를로로 추정해 정규화한다.
평균 커버리지 86.3%, 신뢰 프레임 97.9%, 같은 표본에서 **2.16 → 2.41 (+11.4%)**.

### 좌표계 함정

StatsBomb은 **행위 팀이 항상 좌→우로 공격하는 팀별 미러 좌표계**를 쓴다.
같은 물리적 지점이 A팀 이벤트에서 `x=30`, B팀 이벤트에서 `x=90`으로 기록된다.

`Pressure`와 그 `related_events`의 좌표를 대조해 실증했다 —
미러 변환 시 오차 0.1~4.7 유닛, 미변환 시 8.3~78.3 유닛.
좌우 채널(`y≈0`이 좌측)은 쿠쿠렐라(평균 y 11.6)·카르바할(69.5)과 코너킥 좌표로 교차검증했다.
**초기 집계에서 이 라벨이 뒤집혀 있어 "우측이 생산성 축"이라는 정반대 결론이 나올 뻔했다.**

### 프리즈프레임 선수 식별

360에는 **선수 신원이 없다** — 좌표와 teammate/keeper/actor 플래그뿐이다.
같은 시점(±5초) 이벤트의 선수별 위치와 프리즈프레임 좌표를 공간 매칭해 이름을 복원하되,
독립 최근접이 아니라 **1:1 상호배타 배정**으로 푼다.
독립 최근접을 쓰면 한 선수가 서로 다른 두 좌표에 동시에 배정되는 물리적으로 불가능한 결과가 나온다
(초기 구현에서 그리즈만·오야르사발이 각각 두 곳에 중복 배정됐다).
매칭 오차 4 SB유닛을 넘으면 미식별로 남긴다. 복원된 이름은 **추정치이며 원본 데이터가 아니다**.

## 저장소 구조

```
src/press/
  config.py        분석 파라미터 (임계값 단일 출처)
  statsbomb.py     데이터 로딩 · 좌표 규약 · 단위 환산
  triggers.py      압박 온셋 탐지 + 트리거 7분류
  convergence.py   360 수렴 지수 + 가시성 보정 (몬테카를로)
  identify.py      프리즈프레임 선수 1:1 식별
  pipeline.py      Press Chain 4단계 분석 · 팀 프로파일
scripts/
  run_team.py        한 팀 심층 분석 (트리거 · 곡선 · 구역 지도)
  run_tournament.py  24개국 대조 + 상관/회귀
  make_vignette.py   리포트용 사례 장면 선정 + 선수 이름 복원
report/
  press-trigger-anatomy.html   최종 리포트 (SVG 직접 구현)
```

## 실행

의존성 없음 — Python 3.11 표준 라이브러리만 사용한다.
데이터는 최초 실행 시 StatsBomb 저장소에서 `data/` 로 내려받고 이후 재사용한다(약 540MB).

```bash
python3 scripts/run_team.py --team Spain   # → outputs/spain.json
python3 scripts/make_vignette.py           # → outputs/vignette.json
python3 scripts/run_tournament.py          # → outputs/teams.json  (51경기, 약 30초)
```

`src/press/config.py`의 임계값을 바꾸면 파이프라인 전체가 같은 정의로 재실행된다.

## 한계

- **표본** — 공중볼 28건·백패스 23건은 비율의 신뢰구간이 넓다. 조별리그 3경기만 치른 팀도 마찬가지다.
- **관측자 정의** — `Pressure`는 StatsBomb 수집자의 판단이 개입한 이벤트이며 물리적 거리 임계값이 아니다.
- **상대 수준 미보정** — 회수율은 상대 빌드업 역량에 좌우된다. 라인 높이 역시 상대가 물러서 준 결과일 수 있어
  `R²=0.599`는 상관이지 인과가 아니다. 상대 조정 모델이 다음 단계 과제다.
- **가시성 보정 가정** — 보이지 않는 구역의 선수 밀도가 보이는 구역과 같다고 가정한다.
- **선수 식별** — 근접 이벤트 기반 추정이며 볼에서 먼 선수일수록 신뢰도가 떨어진다.
