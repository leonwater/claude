# 자료퀴즈 — 출퇴근길 객관식 학습 앱

학습 자료(PDF)의 내용만으로 만든 객관식 문제를 짧은 이동 시간에 풀고, 틀린 문제는 오답노트로 반복하는 **개인용 안드로이드 앱**입니다.
스토어에 배포하지 않고 APK를 직접 설치해 혼자 사용합니다. 서버 없이 모든 데이터가 휴대폰 안에 저장되며 오프라인에서 동작합니다.

📲 **최신 APK:** [Releases](../../releases/latest) 에서 `studyquiz-1.0.N.apk` 를 받아 설치

## 주요 기능

| 기능 | 내용 |
|---|---|
| **내장 문제은행** | ADsP 1·2·3과목 핵심 정리 PDF로 만든 518문항. API 키 없이 바로 풀 수 있음 |
| **문제 유형** | 용어·개념을 고르는 문제와 **옳은 것 / 옳지 않은 것**을 고르는 문장형 문제(PDF 강조 글씨 중심) |
| **과목 선택** | 1과목 / 2과목 / 3과목 / 종합 중 선택, 과목별로 정한 문항 수(아래 표) |
| **무작위 반복 출제** | 안 푼 문제부터 무작위로 출제. 과목 전체를 한 바퀴 돈 뒤 다음 바퀴로 넘어감 |
| **이어 풀기** | 퀴즈 중 앱을 꺼도 다시 열면 같은 문제·같은 보기 순서로 이어짐 |
| **끝내기** | 끝내기를 눌러야 새 퀴즈를 시작할 수 있음(진행 중에는 시작 버튼 잠금) |
| **풀이 팝업** | 답을 고르면 결과(정답/틀림, 정답 번호)만 보이고, **풀이 보기**를 누르면 풀이가 팝업으로 열림. 휴대폰 뒤로 가기로 팝업만 닫힘 |
| **오답 해설** | 풀이에 **내가 고른 선지에 대한 설명**, `정답: ③ …`, 해설, PDF 근거 문장을 함께 표시 |
| **용어정리** | 풀이 맨 밑에 그 문제와 보기에 나온 PDF 용어와 설명을 표시 |
| **그림 문제** | PDF의 그래프·표·R 출력 29개를 사용한 43문항. 그림을 누르면 확대 |
| **오답노트** | 틀린 문제 자동 등록, 정답률 표시, 정답률 70% 초과 시 졸업 |
| **내 자료로 문제 만들기** | PDF·DOCX·TXT·MD를 올리고 Claude API로 문제은행 생성(선택 기능, API 키 필요) |
| **백업** | 전체 데이터를 JSON으로 내보내기/복원 |

## 내장 문제은행: ADsP 518문항

원본: `ADsP 1·2·3과목 핵심 정리` PDF(33쪽). 문제 데이터는 [`src/data/adsp_bank.json`](src/data/adsp_bank.json), 그림은 [`public/adsp/`](public/adsp/).

| 과목 | 문항 | 그림 문제 | 단원별 문항 |
|---|---:|---:|---|
| 1과목 데이터 이해 | 112 | 0 | 데이터의 이해 57 · 가치와 미래 40 · 데이터 사이언스 15 |
| 2과목 데이터분석 기획 | 97 | 6 | 분석 기획의 이해 55 · 분석 마스터플랜 42 |
| 3과목 데이터분석 | 309 | 37 | 데이터 마트 27 · 통계 기초 42 · 확률분포·추정·검정 53 · 회귀 38 · 다변량·시계열 32 · 데이터 마이닝 117 |
| **합계** | **518** | **43** | |

문제 유형: 문제 끝이 '옳은 것은?'인 문제 81개, '옳지 않은 것은?'인 문제 51개입니다. 이 중 98개는 PDF의 **주황(빨강) 강조 글씨**를 중심으로 만든 문장형 문제입니다.

품질 규칙:

- **PDF 내용만 사용** — 모든 문항에 정답 근거 문장(`sourceQuote`)이 있고, 이 문장이 PDF 텍스트에 글자 그대로 있는지 스크립트로 대조합니다(공백만 무시). 불일치 0건.
- **중복 제거** — 문항마다 묻는 개념(`concept`)이 다르고, 답이 겹치는 문항은 뺐습니다.
- **정답 위치 분산** — 고정 시드로 보기를 섞어 정답이 1~4번에 고르게(117~135개씩) 있습니다.
- **그림 속 정답 가리기** — 칸 하나만 가리면 나머지 칸을 보고 소거법으로 답이 나오므로, 같은 종류의 칸을 모두 `(가)(나)(다)…`로 가리고 그중 하나를 묻습니다(분석 유형 매트릭스, 빅데이터 분석 방법론, 분석 준비도·성숙도, 분석 수준 사분면, 오류표, 오분류표, 첨도 그림, 박스플롯 경계값). Elbow 그래프의 '최적의 K' 표시는 지웠습니다.
- **답이 보이는 문제 고치기** — 문제 문장에 정답 단어가 들어 있거나(예: '논리적 모델링' → 논리적 설계), 암기법('인자기')이 답을 알려 주던 문제 30여 개를 고쳤습니다.
- **강조 글씨 우선** — 새 문제와 고친 문제는 PDF에서 강조된 용어와 표현을 그대로 씁니다.

### 풀이 구성

답을 고르면 화면에는 `결과(정답입니다/틀렸습니다 · 정답 번호)`와 `풀이 보기` · `다음 문제` 버튼만 나옵니다. **풀이 보기**를 누르면 아래에서 팝업이 올라옵니다.

`결과 → 내가 고른 선지(오답일 때) → 정답 → 해설 → PDF 근거 → 오답노트 정답률 → 용어정리(맨 밑)` + 팝업 아래 `닫기` · `다음 문제`

- **내가 고른 선지** — PDF에 그 선지의 내용이 있으면 설명을 보여 줍니다. 용어이면 PDF의 정의, 다른 개념의 설명·값이면 "이것은 ○○의 식입니다"처럼 어느 내용인지와 PDF 근거를 적습니다.
  출제하려고 임의로 만든 선지는 설명을 지어내지 않고 **"PDF에 없는 선지입니다."**로만 표시합니다(1,554개 오답 선지 중 122개). 순서만 바꾼 선지(18개)는 "PDF에 없는 순서입니다. PDF의 순서는 …"로 표시합니다.
- **문장형 문제의 다른 보기** — '옳은 것' 문제의 틀린 문장은 "틀린 설명입니다."와 PDF의 바른 내용을, '옳지 않은 것' 문제의 옳은 문장은 "옳은 설명입니다(PDF 내용과 같음)."을 보여 줍니다.
- **용어정리** — 문제와 보기에 나온 용어를 최대 8개 보여 줍니다(518문항에 1,868줄, 서로 다른 용어 456개).
  설명은 PDF의 `용어 : 설명` 문장을 그대로 가져오거나(자동 추출), PDF 문장을 근거로 직접 적었습니다. 모두 PDF 원문과 대조해 검증합니다.

## 퀴즈·오답노트 규칙

### 과목별 문항 수

| 선택 | 문항 수 선택지 | 기준 |
|---|---|---|
| 1과목 (112) | 10 · 20 · 30 | 30문항 × 4회 ≈ 과목 전체 1회독 |
| 2과목 (97) | 10 · 20 · 30 | 30문항 × 4회 ≈ 과목 전체 1회독 |
| 3과목 (251) | 10 · 25 · 50 | 분량이 많아 최대 50문항 |
| 종합 (518) | 10 · 25 · 50 | 1과목 : 2과목 : 3과목 = **1 : 1 : 3** (50문항이면 10 · 10 · 30) |

10문항은 출퇴근 한 구간(약 5분) 기준입니다.

### 출제 순서 ([`src/lib/quiz.ts`](src/lib/quiz.ts))

1. 문제를 푼 횟수(`timesSeen`)가 가장 적은 묶음에서 먼저 뽑습니다. 그래서 과목 전체를 한 번씩 본 뒤에 다음 바퀴로 넘어갑니다.
2. 그 안에서 단원(섹션)별 문항 수 비율대로 나누고(최대 잉여 배분), 같은 개념은 한 퀴즈에 한 번만 냅니다.
3. 최종 순서와 보기 순서는 무작위입니다. 보기 순서는 퀴즈마다 새로 섞어 위치로 외우지 못하게 합니다.

### 진행 중 퀴즈 ([`src/lib/sessions.ts`](src/lib/sessions.ts))

- 퀴즈를 시작하면 `sessions` 테이블에 문제 목록, 보기 순서, 현재 위치, 답안을 저장합니다.
- 앱을 다시 열면 끝내지 않은 세션으로 바로 이동합니다.
- 끝내지 않은 세션이 있으면 새 퀴즈와 오답 복습 시작 버튼이 모두 잠깁니다. **끝내기**(풀던 중이면 확인 창)를 눌러야 풀립니다.

### 오답노트 ([`src/lib/wrongNote.ts`](src/lib/wrongNote.ts))

- 정답률은 `맞힌 횟수 ÷ 시도 횟수`이며, 처음 틀린 1회를 포함합니다.
- 정답률이 **70%를 넘으면(>)** 졸업합니다. 처음 틀린 문제는 3번 연속 맞히면 75%가 되어 졸업합니다(0/1 → 1/2 → 2/3 → 3/4).
- 졸업한 문제를 다시 틀리면 새로 등록됩니다. 졸업 기록은 지우지 않고 `graduatedAt`으로 남깁니다.

## 설치와 업데이트

1. 휴대폰 Chrome으로 [Releases](../../releases/latest)를 열고 `.apk` 파일을 받습니다.
2. 파일을 열고, "출처를 알 수 없는 앱" 경고가 나오면 **이 출처 허용**을 켭니다. Play 프로텍트 경고는 **무시하고 설치**를 누릅니다.
3. 새 버전은 지우지 말고 덮어 설치합니다. 서명 키가 같아 기록이 유지됩니다.
   앱을 **삭제**하면 기록도 지워지니, 그 전에 설정 → 백업 파일 내보내기를 하세요.

## 구조

```
study-quiz-app/
├─ src/
│  ├─ App.tsx              화면 스택(뒤로 가기 = history 깊이), 시작 시 문제은행 준비·진행 중 퀴즈 복원
│  ├─ screens/             Home · SetDetail(과목·문항 수 선택) · Quiz · WrongNotes · NewSet · Settings
│  ├─ lib/
│  │  ├─ builtin.ts        내장 문제은행을 DB에 넣기(버전이 바뀌면 기록은 두고 문제만 갱신)
│  │  ├─ quiz.ts           출제(덜 푼 문제 우선 → 단원 비율 → 개념 중복 제거), 과목별 문항 수
│  │  ├─ sessions.ts       진행 중 퀴즈 저장·답안 기록·끝내기
│  │  ├─ wrongNote.ts      오답노트 정답률·졸업 규칙
│  │  ├─ answers.ts        답안 1건 기록(풀이 횟수, 시도 기록, 오답노트)
│  │  ├─ db.ts             IndexedDB(Dexie) 스키마, 백업/복원
│  │  ├─ parse.ts          PDF(pdf.js)·DOCX(mammoth)·TXT/MD → 원문 문단
│  │  ├─ sections.ts       문단 → 출제 단위 섹션
│  │  ├─ claude.ts         Claude API 문제 생성 요청(structured output)
│  │  ├─ generate.ts       섹션별 할당량대로 문제은행 채우기
│  │  ├─ verify.ts         근거 문장 원문 대조, 형식·중복 검사, 보기 섞기
│  │  └─ native.ts         안드로이드 전용 처리(공유 창으로 백업, 화면 꺼짐 방지)
│  └─ data/adsp_bank.json  내장 문제은행(518문항)
├─ public/adsp/            문제 그림 29개
├─ android/                Capacitor 안드로이드 프로젝트(서명 키 포함)
├─ e2e/                    브라우저 테스트(휴대폰 화면 크기 Chromium)
└─ tools/adsp-bank/        문제은행 원본(q*.py)과 생성 스크립트
```

### 데이터 모델 (IndexedDB `study-quiz`)

| 테이블 | 내용 |
|---|---|
| `sets` | 학습 세트. 내장 문제은행은 `builtin: "adsp"`, `bankVersion` |
| `sections` | 출제 단위(내장은 단원 11개, 크기 = 단원 문항 수) |
| `questions` | 문제, 보기 4개, 정답, 해설, 근거 문장, 과목, 그림, 용어정리(`glossary`), 보기별 선지 설명(`choiceInfo`), 푼 횟수 |
| `sessions` | 퀴즈 진행 상태(문제 목록, 보기 순서, 위치, 답안, 끝낸 시각) |
| `attempts` | 답안 1건마다 기록 |
| `wrongNotes` | 오답노트(시도·정답 수, 졸업 시각) |
| `files`, `usage` | 사용자가 올린 파일 정보, Claude API 사용량·비용 |

## 개발

```bash
cd study-quiz-app
npm install
npm run dev          # 개발 서버(같은 Wi-Fi의 휴대폰에서 Network 주소로 접속 가능)
npm test             # 단위 테스트(vitest)
npm run typecheck
npm run e2e          # 빌드 후 브라우저 테스트
```

- **단위 테스트 (40개):** 오답노트 졸업 규칙, 비율 배분, 근거 문장 검증, 섹션 분할, 출제, 내장 문제은행(형식, 과목별 출제, 종합 1:1:3, 한 바퀴 출제, 용어정리·선지 설명 빠짐없음)
- **브라우저 테스트 (45개 항목)**
  - `e2e/builtin.mjs`: 과목별 문항 수, 오답 해설·내가 고른 선지·용어정리 위치, 재실행 후 이어 풀기, 새 퀴즈 잠금, 끝내기, 종합 비율, 그림 로딩
  - `e2e/upload.mjs`: 파일 업로드 → 문제 생성(가짜 Claude 응답) → 퀴즈 → 오답노트 졸업 → 오프라인
- **브라우저 준비:** `npx playwright-core install chromium` 으로 받거나 `CHROMIUM_PATH` 환경변수로 Chromium 경로를 지정합니다.

## 빌드와 배포

| 대상 | 방법 |
|---|---|
| **안드로이드 APK** | `study-quiz-app/` 아래 파일을 바꿔 `main` 또는 작업 브랜치에 푸시하면 [`.github/workflows/android-apk.yml`](../.github/workflows/android-apk.yml)이 자동 실행됩니다: 단위 테스트 → `npm run build:android` → `gradlew assembleRelease` → GitHub Release `apk-1.0.<실행번호>` 생성 |
| 문서만 바꿀 때 | 커밋 메시지에 `[skip ci]`를 넣으면 APK를 다시 빌드하지 않습니다 |
| 웹(PWA) | `npm run build` 결과 `dist/`를 HTTPS 정적 호스팅에 올립니다(저장소 루트 `netlify.toml` 사용) |

로컬에서 APK를 만들려면 Android SDK와 JDK 21이 필요합니다: `npm run build:android && cd android && ./gradlew assembleRelease`.

**서명 키:** `android/app/studyquiz.keystore`는 개인 사이드로드용이라 일부러 저장소에 둡니다. 어느 환경에서 빌드해도 서명이 같아야 기록을 지우지 않고 덮어 설치할 수 있기 때문입니다. 이 키로는 공개 배포를 하지 마세요.

## 문제은행 다시 만들기

문제 원본은 [`tools/adsp-bank/`](tools/adsp-bank/)의 `q1.py`(1과목), `q2.py`(2과목), `q3a/q3b/q3c.py`(3과목)입니다. 각 문제의 보기 첫 번째가 정답입니다.
용어정리와 선지 설명은 같은 폴더의 `glossary.py`(PDF에서 용어 자동 추출), `glossary_extra.py`(직접 적은 용어), `choice_notes.py`(오답 선지 설명)로 만듭니다.

```bash
npm run bank -- "/경로/ADsP 핵심정리.pdf"            # 검증 → 그림 자르기 → src/data/adsp_bank.json 생성
npm run bank -- "/경로/ADsP 핵심정리.pdf" --check    # 검증만
```

- 필요한 도구: `poppler-utils`(pdftotext, pdftoppm), Python `Pillow`.
- 원본 PDF는 저작권 때문에 저장소에 넣지 않았습니다.
- 문제·용어·선지 설명을 고쳤다면 [`src/lib/builtin.ts`](src/lib/builtin.ts)의 `ADSP_BANK_VERSION`을 1 올립니다. 앱이 다음 실행 때 풀이 기록은 두고 문제 내용만 갱신합니다.

## 설계 결정과 한계

- **구독 방식 출제:** 내장 문제는 Claude 대화(구독)에서 만들어 앱에 넣었습니다. 앱이 직접 Claude API를 부르는 기능은 사용자 자료용 선택 기능이며, 이때만 API 키와 사용료가 필요합니다.
- **서버 없음:** 데이터는 기기 IndexedDB에만 있습니다. 기기를 바꾸거나 앱을 지우기 전에 백업하세요.
- **스캔 PDF 미지원:** 사용자 자료 업로드는 텍스트가 있는 PDF만 지원합니다.
- **실기기 테스트 미완료:** 실제 안드로이드 기기에서는 아직 검증하지 않았습니다. 휴대폰 화면 크기 Chromium에서 테스트했습니다.

변경 이력은 [CHANGELOG.md](CHANGELOG.md), 초기 기획은 [docs/study-app-pipeline.md](../docs/study-app-pipeline.md)를 참고하세요.
